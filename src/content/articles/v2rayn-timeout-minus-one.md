## 一、先分清两种延迟测试：TCPing 与“真连接延迟”的根本差异

在 v2rayN 主界面中，“测试服务器延迟（Ctrl+R）”对应的是**真连接延迟（Real Delay / URL-Test）**，而“测试 TCP 延迟”仅检测从你本地网卡到中转入口 IP 的端口连通性。理解这一点能瞬间避免大量误判：

| 现象特征 | 大概率故障层级 | 排查重点方向 |
| :--- | :--- | :--- |
| **TCPing 有数字，真连接全 -1** | TLS 握手、鉴权时间或本地内核层异常 | 校准系统时间、检查 Xray/Mihomo 内核、排查杀软拦截 |
| **TCPing 与真连接双双超时 (-1)** | 本地网络出口、运营商封锁或机场入口变更 | 检查系统代理冲突、更换热点对照、更新防失联订阅链接 |
| **仅个别高倍率或冷门地区 -1** | 单条落地机维护或国际链路波动 | 临时改选香港/新加坡/日本等常规低延迟节点，无需重装软件 |
| **打开浏览器可上外网，仅列表显示 -1** | 测速探测 URL 本身被墙内/落地端拦截 | 在 v2rayN 设置中把“延迟测试 URL”改为标准的 `cp.cloudflare.com/generate_204` |

## 二、4 步现场定位：把满屏 -1 拉回正常延迟

### 第一步：校准操作系统精确时间（误判率最高）

现代代理协议（VMess、VLESS、Trojan 及各类 TLS 传输层）对本地与服务器时间差有极高要求，**通常误差超过 60–90 秒即直接拒连**。很多用户主板 CMOS 电池亏电或双系统切换后，系统时间慢了一两小时，所有节点会一视同仁全部报 `-1`。

1. 右键桌面右下角时间 → **调整日期和时间**。
2. 先开启“自动设置时间”，再手动点击一次**立即同步**（若同步超时，可先临时切到手机热点同步时间）。
3. 重启 v2rayN 并单独选中一个主流节点按 `Ctrl+R` 测试。

### 第二步：核对下发协议与底层 Core 核心是否匹配

站内记录显示，不少机场在 `2025–2026` 年逐步从单一 Shadowsocks/Trojan 转向多协议混发，例如 **光速云** 在详表中标注同时存在 VLESS、Shadowsocks 与 AnyTLS 等协议适配说明，**光年梯**、**大佬云**、**闪电鼠** 等则主打 `VLESS + IEPL`。

如果你的 v2rayN 版本过老或误把内核锁死在旧版核心，可能直接看不懂新下发字段：

1. 在 v2rayN 主界面底栏查看当前日志窗口：如果报错包含 `unknown protocol` 或 `core not found`，说明内核不兼容或已缺失。
2. 优先把 **Xray** 与 **sing-box / Mihomo** 核心更新至新版，在“设置 → Core 类型设置”中让 v2rayN 对不同订阅协议保留自动匹配策略。
3. 确认你下载的是带有完整内核的压缩包，且目录已加入安全中心排除项，避免 `xray.exe` 被当成未知二进制文件拦截。

### 第三步：排查并发测速引发的中转入口防火墙限流

部分机场中转入口对“瞬间发起 60 条以上并发 TCP 探测”非常敏感。当你在 v2rayN 里全选整个订阅同时按 `Ctrl+R`，瞬间并发连接可能触发机房防 CC 策略，导致后半段节点被暂时丢包几十秒。

- 解决方式：一次仅选中 5–10 个常用地区节点（例如先选香港组）进行小批量测试；同时把设置中的“并发测速数量”限制在 `4` 到 `6` 之间，比一次扫全表更稳。

### 第四步：检查本地软件冲突与残留代理环境变量

如果你同时开过游戏加速器、老版本 VPN 或未正常退出的 Clash 客户端，系统 `HTTP_PROXY` 环境变量或全局代理可能把 v2rayN 自己的探测包也往死端口里送。排查方法：

1. 在 Windows 底部托盘彻底退出其他所有代理、网游加速器和公司内网 VPN 客户端。
2. 确认 v2rayN 底部状态栏显示为**自动配置系统代理**或暂时切为**清除系统代理**后再点击测速（因为 v2rayN 内置真连接探测本身会直连内部端口，不被系统代理卡住即可）。
3. 若仍全部超时，打开命令提示符查看本机是否可直连外网基础域名；若本地直接断网，请前往 [Windows 代理残留断网急救](/articles/windows-proxy-reset-emergency/) 与 [Wi-Fi 与手机热点对照排查](/articles/wifi-vs-5g-timeout/)。

## 三、自查无误仍无反应？何时该判断为服务端问题

若你已完成时间同步、核心校验并用 **手机 5G 热点** 交叉测试后仍全部显示 `-1`，说明问题大概率落在机场入口本身：

- **订阅地址或域名变更**：检查客户端内更新订阅时是否返回 `404` / `502` 或 SSL 证书错误，可参照 [机场防失联域名找回流程](/articles/find-official-panel-anti-loss/) 核实最新订阅域名。
- **套餐流量耗尽或到期**：很多新手忘记自己购买的是按量计费/低配月付套餐（如 `100GB` 月付在高频 4K 观影或高倍率节点下提前用尽），面板一旦停用订阅节点，客户端就会瞬间全黑报 `-1`。
