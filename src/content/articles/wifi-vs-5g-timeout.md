## 一、建立对照基线：为什么先用手机热点测试如此关键？

在排查任何“全部节点超时”问题前，先用电脑或备用手机连一次**未开代理的手机 5G 热点**：

| 5G 热点对照结果 | 问题所在范围 | 最快验证与解决方向 |
| :--- | :--- | :--- |
| **热点秒连，仅家庭 Wi-Fi 全超时** | **100% 为本地宽带/光猫/路由器故障** | 依次排查网卡 IPv6、光猫 DNS 劫持与 NAT 并发 |
| **热点和家庭 Wi-Fi 同时全部超时** | 客户端系统时间、账号余量或服务端域变更 | 同步系统时钟、查流量余量并排查官网最新入口 |
| **仅部分地区/UDP 端口节点超时** | 校园网/公司网络对高位 UDP 端口 QoS | 优先切换 TCP/443 伪装协议与 BGP 多线入口 |

- **如果热点也全部超时**：优先检查订阅是否过期、账号流量是否用完、系统时间是否正确或机场入口是否维护（对照 [Clash Verge 四步排查](/articles/clash-verge-timeout-triage/)）。
- **如果热点秒连，只有家庭 Wi-Fi / 宿舍校园网全部超时**：立刻停止折腾客户端规则与删改订阅，因为故障 **100% 发生在“电脑网卡 → 路由器 → 光猫 → 本地宽带运营商”这四段之内**。

## 二、家庭 Wi-Fi 节点全部超时的五步精准排查

### 第一步：暂时关闭网卡或路由器的 IPv6 尝试直连

这是过去两年国内家用宽带导致代理超时的头号隐形杀手。当宽带下发了半残的 IPv6 地址，部分客户端内核（或机场解析域名）优先用 IPv6 去握手入口服务器，若其中一跳路由不通，就会全线卡死。

1. 在电脑“网络和 Internet 设置 → 更改适配器选项”中找到当前 Wi-Fi 属性，先取消勾选 `Internet 协议版本 6 (TCP/IPv6)` 后确定。
2. 观察机场客户端节点延迟是否恢复正常。若恢复，说明确认为路由器/运营商 IPv6 链路问题，可在路由器管理后台关闭 IPv6 开关，或在客户端配置中关闭 `ipv6: false`。

### 第二步：排查本机及路由器的 DNS 污染与劫持

不少运营商光猫会把用户的普通 UDP/53 端口 DNS 请求强行引导至本地缓存节点。如果你在客户端的 `dns` 配置中依然依赖未经加密的本地运营商 DNS 解析机场入口域名，可能拿到被污染的假 IP，导致在 Wi-Fi 下所有连接指向黑洞地址。

- **客户端侧优化**：在 Mihomo/Clash 客户端设置内确保启用了系统 DNS 接管或配置可信的 DoH（DNS over HTTPS）做基础域名解析（注意配置合理的国内直连与海外分流，避免全站反噬，参见 [Clash 规则与全局模式](/articles/clash-rule-vs-global/)）。
- **路由器侧优化**：将无线路由器 WAN 口/DHCP 下发的主 DNS 手动改为正规公共解析（如阿里/腾讯 DoT 或规范公共 IP），不要完全依赖光猫自动分配的默认 DNS。

### 第三步：核对多终端网间跨网拥塞与宽带运营商差异

有时并不是家庭 Wi-Fi 硬件坏了，而是你的手机卡（例如中国联通 5G）与家里宽带（例如中国移动或校园网）根本不是同一家运营商。

- 如我们在 [三网晚高峰选线实解](/articles/isp-selection/) 中整理的光速云 2026-08-19 实测所示，三大运营商出口线路在跨网接入上的表现差异很大。如果你家宽带属于对特定非 BGP 入口极其友好的相反阵营，一旦入口服务器只对单线联通或单线电信优化，家用宽带一到晚间 20:30 就容易全线丢包超时，而另一张运营商的手机 5G 热点却畅通无阻。
- **验证方法**：切换同订阅里标注了不同入口地区/专线标签的节点，查看是否只有特定入口节点在家庭 Wi-Fi 下失效。

### 第四步：排查老旧光猫 NAT 连接数打满与路由器防火墙

运营商自带光猫在开启内置无线并负责 PPPoE 拨号时，CPU 与内存往往非常紧张。当你打开浏览器多标签加载、微信下载视频同时代理客户端做节点全量测速，连接表很容易爆满丢包：

- 临时检验：重启光猫和路由器，在仅接入当前这一台设备的前提下测一次单节点延迟。如果重启后头几分钟正常、几十分钟后再次全线超时，基本可锁定为光猫 NAT 性能不足或过热降频。
- 根治办法：联系宽带安装师傅把光猫改为**桥接模式（Bridge）**，由性能合格的千兆家用无线路由器负责 PPPoE 拨号与 NAT 转发。

### 第五步：检查路由器端 MTU 与代理端口协议策略

极少数校园网宿舍或公司访客 Wi-Fi 会封锁高位 UDP 端口（直接掐断依赖 UDP 传输的 Hysteria2 / TUIC 协议），或者因为 PPPoE/VPN 封装嵌套使默认 `MTU 1500` 引发大包分片丢弃，呈现为“延迟数字看得到、打开任何网页一直转圈直至超时”。

- 若你在机场客户端内同时拿到了多种协议节点（例如 **光速云** 等支持的常规 TLS/VLESS 443 伪装端口节点与 QUIC UDP 节点），在公司或校园 Wi-Fi 下优先挑选**基于标准 TCP/443（HTTPS 常见端口）**的节点，跳过纯高位 UDP 端口，通常立刻恢复稳定。
